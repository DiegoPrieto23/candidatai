PRUEBA MANUAL · FASE 09b.1 y 09b.2 · ALERTAS POR CORREO Y BOTÓN «ENVIAR A JOB HUNTER»
=====================================================================================

Objetivo: comprobar con correos y portales reales que
- las alertas de empleo por correo entran solas como ofertas «resumen» en la pantalla «Alertas»,
  sin duplicarse y sin tocar tu buzón;
- el botón «Enviar a CandidatAI» manda la oferta que estás viendo, completa un resumen de una
  alerta sin duplicarlo y, de ahí, sale un CV.
La búsqueda con el navegador del agente (09b.3) tendrá su propia guía.

Duración aproximada: 40 minutos (menos si te saltas IMAP).


REQUISITOS
----------
- Una o varias alertas de empleo activas en los portales que uses (LinkedIn, InfoJobs, Indeed,
  Tecnoempleo…) y algún correo de alerta ya recibido.
- Chrome, Edge o Brave.
- Dos terminales de PowerShell (API y UI) y tu agente para la parte 7.
- Los comandos se ejecutan desde la RAÍZ del repo:
      cd <carpeta-del-repo>
- Rama: main (la fase ya está fusionada) o fase/09b-alertas-captura-busqueda.

Las ofertas que se den de alta son REALES y se quedan en tu base de datos (data/candidatai.db).


PARTE 1 · PREPARAR
------------------
1. Migra la base de datos (la 09b.1 añade la 0007):

      uv run --directory backend cai db upgrade

   Esperado: "Base de datos actualizada: 0006 -> 0007." (o desde la que tengas).

2. Comprueba el entorno:

      uv run --directory backend cai doctor

   Esperado, entre otras:
   - «Alertas por correo»: OK, «sin IMAP (opcional); deja correos .eml o .mbox en data/inbox/».
   - «Botón de captura»: OK, «sin configurar (opcional)…».

3. Arranca la app:
      Terminal 1:   uv run --directory backend cai serve
      Terminal 2:   cd frontend; pnpm dev
   Abre http://127.0.0.1:5173. En el menú superior debe aparecer «Alertas».


PARTE 2 · ALERTAS DESDE UNA CARPETA (SIN IMAP)
----------------------------------------------
1. Exporta dos o tres correos de alertas reales, de portales distintos si puedes.
   En Gmail: abre el correo → «⋮» (Más) → «Descargar mensaje». Se guarda un .eml.

2. Copia los .eml en data\inbox\ (créala si no existe). Copia ADEMÁS uno de cada portal en
   data\inbox\samples\ : con ellos se afinan los parsers (la carpeta samples no se procesa y
   está fuera de git).

3. En la UI, «Alertas» → «Revisar correo ahora».
   Esperado: «Alertas por correo: N correos nuevos, M ofertas, K nuevas (… como resumen)».
   - LinkedIn: siempre como resumen (no se descarga nada de LinkedIn).
   - InfoJobs, Indeed, Tecnoempleo: se intenta la oferta completa; si el portal la bloquea, entra
     como resumen.
   Lo mismo por consola:   uv run --directory backend cai alerts poll

4. Revisa la lista:
   - título, empresa, ubicación y portal correctos en cada fila;
   - primero las que pasan el prefiltro; abajo, «No pasan el prefiltro (N)» con el motivo
     (título que no encaja con tus puestos, zona, seniority del título…);
   - si un correo de un portal no dio ninguna oferta, el aviso «No se encontraron ofertas en un
     correo de …» (indica que su formato no lo reconoce el parser: anótalo).

5. Pulsa otra vez «Revisar correo ahora».
   Esperado: «ningún correo nuevo». Los ficheros de data\inbox\ siguen ahí, sin cambios.

6. Teclado en «Alertas»:
   - J / K (o flechas): moverse;
   - O: abre la oferta en su portal, en una pestaña nueva;
   - D: descartar con motivo (1-6, Intro). Aparece «Descartada … · Deshacer»; prueba Deshacer.
   La cabecera muestra el número de alertas por completar junto a «Alertas».


PARTE 3 · OPCIONAL: IMAP (GMAIL)
--------------------------------
Solo lectura: no marca como leído, no mueve ni borra nada.

1. En Gmail, crea una etiqueta, p. ej. «Alertas empleo», y un filtro que lleve ahí las alertas:
   Configuración → Filtros → Crear filtro → De: jobalerts-noreply@linkedin.com OR
   alertas@infojobs.net OR … (los remitentes de tus alertas) → «Aplicar la etiqueta».
   Marca «Aplicar también a las conversaciones que coincidan» para incluir las ya recibidas.
2. Activa la verificación en dos pasos y crea una contraseña de aplicación:
   myaccount.google.com → Seguridad → Contraseñas de aplicaciones.
3. Añade a .env (raíz del repo):

      CAI_IMAP_HOST=imap.gmail.com
      CAI_IMAP_USER=tu-correo@gmail.com
      CAI_IMAP_PASSWORD=la-contraseña-de-aplicación
      CAI_IMAP_FOLDER=Alertas empleo

4. Reinicia `cai serve` y ejecuta:   uv run --directory backend cai doctor
   Esperado: «Alertas por correo»: OK, «IMAP en solo lectura: … carpeta «Alertas empleo»».
   Con una contraseña mal: ERROR con «contraseña de aplicación».
5. «Revisar correo ahora» en «Alertas». Esperado: lee las alertas de los últimos 21 días.
6. Comprueba en Gmail que esos correos siguen como estaban (sin leer si lo estaban).
7. Con `uv run --directory backend cai worker` en marcha, el correo se lee al arrancar y cada 60
   minutos (config/policies.yaml → email_alerts.poll_minutes).


PARTE 4 · INSTALAR LA EXTENSIÓN
-------------------------------
1. Abre chrome://extensions (en Edge, edge://extensions) y activa «Modo de desarrollador».
2. «Cargar descomprimida» → elige la carpeta extension\ del repo.
   Esperado: «Enviar a CandidatAI» con el id hnaofhehllbkghfehnehamjbkcmdjmle.
3. Fija el botón: icono del puzle → chincheta junto a «Enviar a CandidatAI».
4. Genera el token:

      uv run --directory backend cai capture token

   Cópialo (solo se muestra una vez).
5. Clic derecho en el icono → «Opciones» → pega el token → «Guardar» → «Probar conexión».
   Esperado: «Todo listo: la app responde y acepta este token».
   Prueba también con un token cualquiera: «El token no vale…».
6. `cai doctor`: «Botón de captura»: «token creado; acepta la extensión hnaofheh…».


PARTE 5 · CAPTURAR UNA OFERTA DE LINKEDIN QUE YA ESTÁ EN «ALERTAS»
----------------------------------------------------------------
1. En «Alertas», elige una oferta de LinkedIn y pulsa O (se abre en LinkedIn; inicia sesión si
   hace falta).
2. Pulsa el botón de la extensión.
   Esperado: popup con «Completada», el título y la empresa, y «Abrir ficha». El icono queda
   con ✓ en esa pestaña.
3. «Abrir ficha»: la oferta está en «Por extraer», con la descripción completa y el evento
   «Descripción capturada». Ya no aparece en «Alertas» y NO hay una oferta duplicada en la
   bandeja.
4. Vuelve a pulsar el botón en la misma oferta. Esperado: «Ya estaba» y el icono con =.
5. Repite desde la vista de búsqueda de LinkedIn (lista a la izquierda, oferta a la derecha,
   URL con ?currentJobId=…) con otra oferta de «Alertas». Esperado: también «Completada».


PARTE 6 · CAPTURAR OFERTAS NUEVAS DE VARIOS PORTALES
---------------------------------------------------
Para cada portal que uses (LinkedIn, InfoJobs, Indeed, Tecnoempleo y la página de empleo de
alguna empresa):
1. Abre una oferta que NO tengas en la app y pulsa el botón.
   Esperado: «Nueva: lista para extraer». En la ficha, revisa título, empresa, ubicación y que la
   descripción sea la de la oferta (sin menús, ofertas similares ni botones).
2. Si sale «No se encontró la descripción» o «No se encontró la empresa»: selecciona con el ratón
   el texto de la oferta, empresa incluida, y vuelve a pulsar. Esperado: «Nueva» y, en el popup,
   «Se envió el texto que tenías seleccionado».
3. Casos de error:
   - con `cai serve` parado: «La app no responde. ¿Está «cai serve» en marcha?»;
   - en chrome://extensions: «No se puede leer esta página».


PARTE 7 · DE LA CAPTURA AL CV (CRITERIO DE ACEPTACIÓN)
-----------------------------------------------------
1. En tu agente: /procesar-ofertas → las capturadas pasan a «Por revisar».
2. En «Triaje», aprueba la oferta de LinkedIn de la parte 5.
3. En tu agente: /generar-cv <id> → la oferta llega a «CV listo» con su PDF.


PARTE 8 · PLATAFORMAS (09b.3)
-----------------------------
Requisitos: `cai db upgrade`, `cai serve` y `pnpm dev`. Cierra antes Claude Code una vez y vuelve a
abrirlo, para que el servidor MCP cargue las herramientas nuevas.
1. En una sesión NUEVA de Claude Code (solo para esto): /buscar-ofertas configurar
   Esperado: te pregunta dónde buscas, recomienda de 3 a 6 portales con un motivo y guarda los que
   apruebes con `save_source`. Pídele que guarde también LinkedIn.
2. Abre http://127.0.0.1:5173/plataformas.
   Esperado: las plataformas por prioridad, con sus búsquedas y «El agente aún no la ha
   recorrido». LinkedIn aparece desactivada y con «Riesgo para tu cuenta».
3. Cambia la prioridad y el acceso de una plataforma. Recarga: se conservan.
4. Pulsa el interruptor de LinkedIn. Esperado: el aviso de riesgo. «Cancelar» no cambia nada.
   Si quieres probarlo, «Activar bajo mi responsabilidad» la activa. Desactívala después si no la
   vas a usar.
5. Comprobación de la regla dura: en la sesión del agente pide «guarda LinkedIn con
   allow_agent_browsing true». Esperado: error `not_allowed` y explicación de que solo tú puedes
   activarla.


PARTE 9 · BÚSQUEDA CON NAVEGADOR (CRITERIO DE ACEPTACIÓN)
--------------------------------------------------------
Con Claude in Chrome conectado, en una sesión nueva de Claude Code:
1. /buscar-ofertas <una plataforma de acceso libre, p. ej. Tecnoempleo>
   Esperado: abre tus búsquedas, lee como mucho 2 páginas con pausa entre ellas, abre solo las
   ofertas que encajan (hasta max_offers), las da de alta y termina con un resumen por plataforma.
   No pulsa «Inscribirme», «Guardar» ni similares, ni sale del dominio del portal.
2. En «Plataformas»: el último recorrido con encontradas, nuevas, ya conocidas e incidentes.
3. En la bandeja («Por extraer»): las ofertas nuevas. Su historial dice que entraron por la
   plataforma (evento `found` con `source_id`).
4. Repite el paso 1. Esperado: las mismas ofertas cuentan como «ya conocidas», sin duplicados.
5. Si aparece un captcha o un login inesperado: el agente para esa plataforma, lo anota como
   incidente y no intenta resolverlo.


QUÉ ANOTAR
----------
Por cada fallo, para poder ajustar los parsers y extractores:
- Alertas: portal, qué campo salió mal en «Alertas» (título, empresa, ubicación) o si el correo
  no dio ofertas. Deja ese correo en data\inbox\samples\.
- Botón: portal, URL de la oferta, qué campo falló (título, empresa, ubicación, descripción) y
  qué se coló en la descripción, si algo.
- Si el prefiltro dejó abajo algo que sí te interesaba, o arriba algo irrelevante.
- Si «Revisar correo ahora» tarda mucho (lee IMAP y descarga páginas dentro de la petición).
- Búsqueda con navegador: plataforma, si se saltó alguna regla (dominios, botones, límites), qué
  ofertas entraron mal (título, empresa, texto) y los incidentes.


LIMPIEZA
--------
- Las ofertas se quedan (son reales). Las de «Alertas» que no completes caducan solas a los 21
  días (email_alerts.summary_expire_days).
- Para dejar de leer el correo: quita las variables CAI_IMAP_* de .env y vacía data\inbox\.
- Para invalidar el token: vuelve a ejecutar `cai capture token` (el anterior deja de valer).
- Para quitar la extensión: chrome://extensions → «Quitar».
