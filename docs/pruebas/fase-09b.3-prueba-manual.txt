PRUEBA MANUAL · FASE 09b.3 · PLATAFORMAS Y BÚSQUEDA CON NAVEGADOR
=================================================================

Objetivo: comprobar con portales reales que
- el agente configura contigo las plataformas donde buscar (`search-jobs configurar`) y las
  ves y ajustas en la pantalla «Plataformas»;
- LinkedIn queda desactivado y solo tú puedes activarlo, confirmando el riesgo;
- el agente recorre con tu navegador una plataforma de acceso libre, da de alta lo que encaja sin
  duplicar y anota el recorrido (criterio de aceptación).

Duración aproximada: 30 minutos.


REQUISITOS
----------
- Claude Code con Claude in Chrome conectado (extensión instalada y con permiso en el portal que
  vayas a probar). Otros agentes con acceso al navegador también valen; anota cuál usas.
- Perfil importado (`cai profile import`) con `preferences` (puestos, zonas, modalidad).
- Dos terminales de PowerShell (API y UI).
- Los comandos se ejecutan desde la RAÍZ del repo:
      cd <carpeta-del-repo>
- Rama: main (la fase ya está fusionada).

Las ofertas que se den de alta son REALES y se quedan en tu base de datos (data/candidatai.db).


PARTE 1 · PREPARAR
------------------
1. Cierra Claude Code (su servidor MCP bloquea el entorno) y sincroniza:
       uv sync --directory backend
       uv run --directory backend cai db upgrade
2. Arranca la API y la UI, cada una en su terminal:
       uv run --directory backend cai serve
       cd frontend; pnpm dev
3. Abre Claude Code de nuevo, así su servidor MCP carga las herramientas nuevas (`list_sources`,
   `save_source`, `record_source_run`).
   Comprobación rápida en otra terminal:
       uv run --directory backend cai sources list --kind agent_browse
   Esperado: «No hay fuentes…» (o tus plataformas, si ya había).


PARTE 2 · CONFIGURAR PLATAFORMAS
--------------------------------
1. En una sesión NUEVA de Claude Code (solo para esto, sin mezclar con desarrollo):
       /search-jobs configurar
   Esperado:
   - te pregunta en qué portales buscas, en cuáles tienes cuenta y cuáles no quieres;
   - recomienda de 3 a 6 plataformas, cada una con un motivo ligado a tu perfil;
   - construye contigo las búsquedas (URLs ya filtradas) y guarda las que apruebes.
2. Pídele que guarde también LinkedIn con una búsqueda tuya.
   Esperado: la guarda DESACTIVADA y te explica que solo tú puedes activarla en «Plataformas».
3. Regla dura: pídele «guarda LinkedIn con allow_agent_browsing true».
   Esperado: error `not_allowed` y no cambia nada.
4. Opcional: pídele que guarde en una plataforma conocida (p. ej. InfoJobs) una búsqueda de otro
   dominio. Esperado: error, «no es de InfoJobs».


PARTE 3 · PANTALLA «PLATAFORMAS»
--------------------------------
1. Abre http://127.0.0.1:5173/plataformas.
   Esperado: las plataformas ordenadas por prioridad, con su id (`tecnoempleo`…), sus búsquedas
   (enlaces que abren en pestaña nueva), «Hasta N ofertas por recorrido», los límites de
   config/policies.yaml arriba y «El agente aún no la ha recorrido».
   LinkedIn aparece «Desactivada» y con la etiqueta «Riesgo para tu cuenta».
2. Cambia la prioridad y el acceso de una plataforma. Recarga la página: se conservan.
3. Desactiva y reactiva una plataforma que no sea LinkedIn: sin diálogo.
4. Pulsa el interruptor de LinkedIn.
   Esperado: el aviso de riesgo. «Cancelar» no cambia nada.
   Si quieres probarlo: «Activar bajo mi responsabilidad» la activa. Vuelve a desactivarla si no
   vas a usarla.
5. Con LinkedIn activada por ti, pide al agente que la vuelva a guardar (p. ej. con otra
   prioridad). Esperado: sigue activada («la activó el usuario»).


PARTE 4 · BÚSQUEDA CON NAVEGADOR (CRITERIO DE ACEPTACIÓN)
--------------------------------------------------------
Usa una plataforma de acceso libre (`access: free`), por ejemplo Tecnoempleo.
1. En una sesión nueva de Claude Code:
       /search-jobs <nombre de la plataforma>
   Mientras trabaja, observa que:
   - abre solo tus búsquedas y no sale del dominio del portal;
   - lee como mucho 2 páginas de resultados, con una pausa entre ellas;
   - abre solo las ofertas que encajan con tus preferencias, hasta el máximo de la plataforma;
   - no pulsa «Inscribirme», «Guardar», «Seguir» ni envía formularios;
   - termina con un resumen: encontradas, nuevas, ya conocidas e incidentes.
2. En «Plataformas»: el último recorrido con esas cifras.
3. En la bandeja, filtro «Por extraer»: las ofertas nuevas. En su ficha, el historial dice que
   entraron por la plataforma (evento `found` con su `source_id`).
4. Repite el paso 1.
   Esperado: lo mismo cuenta como «ya conocidas»; ninguna oferta duplicada.
5. Si aparece un captcha, un aviso anti-bot o un login inesperado: el agente para esa plataforma,
   lo anota como incidente (se ve en «Plataformas») y no intenta resolverlo.
6. Opcional: /process-jobs en otra sesión para extraerlas.


QUÉ ANOTAR
----------
- Agente y navegador usados (para docs/AGENTS_COMPAT.md).
- Si se saltó alguna regla: dominios, botones, número de páginas u ofertas, pausas.
- Ofertas que entraron mal: título, empresa, ubicación o texto (menús, ofertas similares…).
- Recomendaciones de `configurar` que no tenían sentido para tu perfil, o portales caídos o de
  pago sin avisar.
- Incidentes que aparecieron y si el agente paró como debía.


LIMPIEZA
--------
- Las ofertas se quedan (son reales).
- Para que el agente deje de recorrer una plataforma: desactívala en «Plataformas».
- LinkedIn: déjala desactivada salvo que quieras asumir el riesgo para tu cuenta.
