Fase 26 · Prueba manual (macOS, Linux y Docker)
=================================================

Se va completando en cada subfase. Linux se prueba en WSL2 (Windows 11 trae WSLg, con entorno
gráfico) o en una máquina virtual; macOS, en la CI y a mano si alguien tiene un Mac.


26.1 · Núcleo multiplataforma
-----------------------------

Preparación en WSL2 (Ubuntu), una sola vez:

  1. Abre «Ubuntu» desde el menú Inicio. Comprueba que hay entorno gráfico:
       echo $DISPLAY $WAYLAND_DISPLAY        (debe salir algo como «:0 wayland-0»)
  2. Instala uv, una terminal y, si quieres, LibreOffice:
       curl -LsSf https://astral.sh/uv/install.sh | sh
       sudo apt update && sudo apt install -y gnome-terminal libreoffice-writer
  3. Clona el repositorio DENTRO de Linux (no en /mnt/c: es lento y los permisos cambian):
       git clone <tu repo> ~/candidatai && cd ~/candidatai && git checkout fase/26-multiplataforma
  4. Instala tu agente en WSL (p. ej. Claude Code: https://docs.claude.com/claude-code) y
     comprueba que `claude --version` responde.
  5. Prepara la app:
       cd backend && uv sync && uv run cai db upgrade
       uv run pytest tests/test_terminals.py tests/test_agent_runs.py -q
     Los tests marcados «necesita macOS o Linux» deben pasar aquí, no saltarse.

A) Diagnóstico
  - `uv run cai agents doctor` dice «Terminal para los botones: gnome-terminal (…)» (o la que
    tengas). Con `CAI_TERMINAL=kitty uv run cai agents doctor` y sin kitty instalado, dice que no
    la encuentra.
  - `uv run cai paths` enseña «Datos de la app instalada: /home/<tú>/.local/share/candidatai/data».

B) Un botón «en tu agente» abre una terminal
  - Siembra la demo y arranca: `uv run cai demo seed` y sigue sus indicaciones (ahora en bash), o
    con la UI compilada: `uv run cai start`. El navegador de Windows abre la app (WSL reenvía
    127.0.0.1).
  - Pulsa «Procesar ofertas» → «En terminal». Se abre una ventana de gnome-terminal en la carpeta
    del repositorio con tu agente arrancado y la orden del skill ya escrita.
  - En esa ventana, al salir del agente, queda un shell abierto. `echo $CAI_CLIENT_NAME` dice el
    agente; `echo ${ANTHROPIC_API_KEY-sin}` dice «sin» aunque la tuvieras exportada.
  - Desinstala o renombra la terminal (o pon `CAI_TERMINAL=no-existe` en .env y reinicia): el
    botón dice que no encuentra la terminal y copia la orden.

C) Segundo plano: cancelar no deja procesos huérfanos
  - Con Claude Code u OpenCode instalados en WSL, lanza «Procesar ofertas» → «En segundo plano» y,
    mientras corre, cancélalo en la página «Agente».
  - `ps -ef | grep -E "claude|opencode|cai-mcp" | grep -v grep` no enseña nada de esa ejecución.
  - Repite y, en vez de cancelar, cierra `cai start` con Ctrl+C: tampoco queda nada vivo, y la
    ejecución aparece como fallida («Se paró el worker…»).

D) LibreOffice y «Abrir carpeta»
  - Con libreoffice-writer instalado, `uv run cai doctor` lo encuentra y la demo genera PDF y DOCX.
  - «Abrir carpeta» en «Mi perfil» abre el explorador (xdg-open) o, si no hay, enseña la ruta.

E) Windows no cambia
  - En Windows, los botones siguen abriendo Windows Terminal (o PowerShell) como antes, y
    `CAI_TERMINAL` no cambia nada.


26.2 · Instalador para macOS y Linux
------------------------------------

En WSL2 (Ubuntu), en la rama: crea primero una release local (sin publicar nada), desde la raíz del
repositorio clonado en Linux y con la UI compilada (`cd frontend && pnpm install && pnpm build`):

    bash install.sh --source "$PWD"         # o un candidatai.zip descargado de una release

A) Prueba en seco
  - `bash install.sh --dry-run --source "$PWD"` explica los cinco pasos y termina con «no se ha
    cambiado nada». `ls ~/.local/share/candidatai` no existe (si no habías instalado antes).

B) Instalar
  - Sin `--dry-run`: instala uv si no lo tenías, `uv sync`, Chromium y la base de datos. Si
    Chromium no arranca, enseña el comando de `playwright install-deps` (con sudo) sin ejecutarlo.
  - `~/.local/share/candidatai/app` tiene la app; `…/data`, tus datos; `…/app/.env` dice
    `CAI_DATA_DIR="…/data"`.
  - En el menú de aplicaciones de Windows aparece «CandidatAI (Ubuntu)» con el icono (WSLg los
    exporta). Ábrelo: se abre una terminal con `cai start` y el navegador en http://127.0.0.1:8000.
    Ciérrala: la app se para (`ps -ef | grep cai` sin nada).

C) Reinstalar no toca tus datos
  - Siembra algo (sube un CV o `uv run --directory ~/.local/share/candidatai/app/backend cai demo
    seed --dir ~/.local/share/candidatai/data`… o crea un fichero en `…/data`), añade una línea
    tuya a `…/app/.env` y vuelve a instalar: los datos y tu línea siguen ahí.

D) Desinstalar
  - `bash install.sh --uninstall`: se van la app y el acceso directo; `…/data` sigue.
  - `bash install.sh --uninstall --remove-data`: pide escribir «borrar»; con otra cosa, no borra.

E) macOS (si alguien tiene un Mac)
  - El mismo recorrido: la app en `~/Library/Application Support/CandidatAI/app` y
    `~/Applications/CandidatAI.app` con el icono, que abre Terminal (la primera vez macOS pide
    permiso para controlar Terminal).
