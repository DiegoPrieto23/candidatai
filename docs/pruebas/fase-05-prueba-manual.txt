PRUEBA MANUAL · FASE 05 · PERFIL DEL CANDIDATO
===============================================

Objetivo: comprobar que el perfil se valida con errores claros, se versiona sin duplicados y que un
agente real (Claude Code) lo lee por MCP con get_profile SIN email, teléfono ni datos privados.

Duración aproximada: 15 minutos.


REQUISITOS
----------
- Esta prueba usa el perfil FICTICIO demo/profile.example.yaml (Lucía Varela). No uses aún tu CV:
  tu perfil real se crea después, con el skill update-profile (ver «Después de la prueba»).
- Para no mezclar nada con tu base de datos real, toda la prueba trabaja en un directorio de datos
  aparte, data/prueba-05/ (dentro de data/, así que git lo ignora). Lo elige la variable
  CAI_DATA_DIR, que solo vive en la ventana de PowerShell donde la pongas.
- Todos los comandos son de PowerShell y se ejecutan desde la RAÍZ del repo:
      cd <carpeta-del-repo>   # p. ej. "C:\Users\<tu-usuario>\...\job-search"
- Rama de la fase:
      git switch fase/05-perfil

IMPORTANTE: haz toda la prueba en la MISMA ventana de PowerShell. Si abres otra, vuelve a poner
CAI_DATA_DIR (paso 1) o estarás trabajando sobre tu base de datos real.


PARTE 1 · PREPARAR
------------------
1. Apunta la app al directorio de prueba y crea su base de datos:

      $env:CAI_DATA_DIR = "data/prueba-05"
      uv run --directory backend cai db upgrade

   Esperado: "Base de datos actualizada: vacía -> 0002."

2. Actualiza también tu base de datos real a la migración nueva (0002). Se hace en una línea
   que quita la variable solo para ese comando y la vuelve a poner:

      Remove-Item Env:CAI_DATA_DIR; uv run --directory backend cai db upgrade; $env:CAI_DATA_DIR = "data/prueba-05"

   Esperado: "Base de datos actualizada: 0001 -> 0002." La migración no borra nada: solo cambia un
   índice de la tabla de perfiles, que aún está vacía.


PARTE 2 · VALIDAR
-----------------
3. Valida el perfil de ejemplo:

      uv run --directory backend cai profile validate demo/profile.example.yaml

   Esperado:
      Perfil válido: …\demo\profile.example.yaml
      2 experiencias, 5 logros, 12 skills, 2 historias.

4. Crea el perfil de trabajo y rómpelo a propósito:

      uv run --directory backend cai profile init

   Esperado: "Creado …\data\prueba-05\profile.yaml a partir del ejemplo…".
   Ábrelo (notepad data/prueba-05/profile.yaml) y haz estos TRES cambios. Guarda al terminar.
     a) En la experiencia de DataGal, cambia el id del primer logro «a1» por «A 1».
     b) En la primera skill (Python), cambia «level: F» por «level: X».
     c) En la primera experiencia, cambia «start: 2024-03» por «start: 2024-13».

      uv run --directory backend cai profile validate

   Esperado: "Error: Perfil no válido (3 errores)…" y una línea por error con su ruta:
      - experience[0].start: Debe ser una fecha con formato AAAA-MM (p. ej. 2024-03). (recibido: '2024-13')
      - experience[1].achievements[0].id: Id no válido: minúsculas, dígitos, … (recibido: 'A 1')
      - skills[0].level: Debe ser uno de: F, C+, C, B. (recibido: 'X')

5. Deshaz los tres cambios y prueba ahora un error ENTRE secciones: en la historia st-migracion,
   cambia «evidence: [exp-norteconsulting/a1]» por «evidence: [exp-norteconsulting/a9]».

      uv run --directory backend cai profile validate

   Esperado: "- stories[0].evidence[0]: La evidencia no existe: … (recibido: 'exp-norteconsulting/a9')".
   Vuelve a dejarlo en «a1» y comprueba que valida:

      uv run --directory backend cai profile validate

   Nota: los errores entre secciones (ids repetidos, skills no declaradas, evidencias) solo
   aparecen cuando los campos sueltos ya están bien. Un perfil muy roto se corrige en dos pasadas.


PARTE 3 · VERSIONAR
-------------------
6. Importa el perfil dos veces:

      uv run --directory backend cai profile import
      uv run --directory backend cai profile import

   Esperado: "Perfil importado: versión 1." y después "Sin cambios: sigue vigente la versión 1."

7. Cambia algo que NO sea contenido (añade una línea de comentario «# prueba» al final del
   fichero) e importa:

      uv run --directory backend cai profile import

   Esperado: "Sin cambios: sigue vigente la versión 1." (comentarios y formato no cuentan).

8. Cambia contenido de verdad: en «headline», quita « · Power BI». Importa y mira el diff:

      uv run --directory backend cai profile import
      uv run --directory backend cai profile diff

   Esperado: "Perfil importado: versión 2." y un diff con una línea «-headline: …Power BI» y otra
   «+headline: …» sin Power BI.

9. Comprueba que los datos privados no salen en el diff: en «private», cambia
   «salary_floor_eur: null» por «salary_floor_eur: 12345». Importa y mira el diff:

      uv run --directory backend cai profile import
      uv run --directory backend cai profile diff

   Esperado: "versión 3" y un diff con «private: <oculto>» y «# private: ha cambiado». El número
   12345 NO aparece.


PARTE 4 · VISTA PÚBLICA POR CLI
-------------------------------
10. Mira lo que verá un agente:

      uv run --directory backend cai profile show

   Esperado: "# Perfil, versión 3 (sin email, teléfono ni privados)" y el perfil en YAML. Busca y
   comprueba que NO aparecen: lucia.varela@example.com, +34 600 000 000, private ni 12345. SÍ
   aparecen los niveles de las skills (F, C+…) y «nda: true» en el logro del asistente LangChain.
   El LinkedIn y el GitHub (lucia-varela-demo) sí salen: son públicos.

11. Por secciones y con una sección que no existe:

      uv run --directory backend cai profile show --sections personal,skills --json
      uv run --directory backend cai profile show --sections skills,private --json

   Esperado: el primero devuelve solo schema_version, personal (sin email ni phone) y skills. El
   segundo, un error validation_error en «sections.1» que dice qué secciones valen.


PARTE 5 · CLAUDE CODE (MCP)
---------------------------
12. Cierra la sesión de Claude Code que tengas abierta (/exit). En ESTA misma ventana de
    PowerShell (con CAI_DATA_DIR puesto), arranca Claude Code en la raíz del repo:

      claude

    Así el servidor MCP hereda CAI_DATA_DIR y lee el perfil de prueba, no tu base de datos real.

13. Escribe /mcp y comprueba que candidatai aparece conectado. Pídele a Claude:

      Llama a la herramienta get_profile de candidatai y dime: el nombre, la ciudad, cuántas
      experiencias y cuántas historias hay, si ves algún email, teléfono o salario, y qué
      versión de perfil es.

    Esperado: Lucía Varela Otero, Santiago de Compostela, 2 experiencias, 2 historias, versión 3,
    y que NO ve email, teléfono ni salario. No debe pedirte permiso para get_profile (es de solo
    lectura y está permitido en .claude/settings.json).

14. Pide solo una parte:

      Llama a get_profile solo con las secciones stories y preferences y resúmelas.

    Esperado: las dos historias STAR y las preferencias (roles, seniority, modalidad…). Nada de
    personal ni de experiencia.

15. Sal de Claude Code (/exit).


PARTE 6 · AUDITORÍA
-------------------
16. Cada llamada del agente queda registrada con las secciones pedidas y nunca con el perfil:

      uv run --directory backend python -c "import sqlite3; c=sqlite3.connect('../data/prueba-05/candidatai.db'); [print(r) for r in c.execute('select channel, client_name, tool, args_summary, ok from mcp_calls')]"

    Esperado: filas con channel "mcp", client_name "claude-code", tool "get_profile" y, en la del
    paso 14, args_summary con ["stories", "preferences"]. Las de CLI con --json del paso 11 salen
    con channel "cli".


LIMPIAR AL TERMINAR
-------------------
17. Borra el directorio de prueba y quita la variable:

      Remove-Item -Recurse -Force data/prueba-05
      Remove-Item Env:CAI_DATA_DIR

    Tu base de datos real (data/candidatai.db) queda en la versión 0002 y sin perfil.


PROBLEMAS FRECUENTES
--------------------
- "La base de datos no está al día": falta el paso 1 (o el 2, si quitaste CAI_DATA_DIR).
- "Ya existe …\profile.yaml: no se sobrescribe" en el paso 4: ya lo creaste antes. Sigue con él
  o bórralo (Remove-Item data/prueba-05/profile.yaml) y repite.
- get_profile devuelve "Aún no hay perfil importado": Claude Code no se arrancó desde la ventana
  con CAI_DATA_DIR, así que mira tu base de datos real. Sal y repite el paso 12.
- /mcp muestra candidatai como "failed": ejecuta a mano "uv run --directory backend cai-mcp" y
  mira el error (también en data/prueba-05/logs/mcp.log).
- Las tildes salen raras en «cai --help»: es la deuda conocida de la fase 02; el resto de
  comandos las muestran bien.


DESPUÉS DE LA PRUEBA · TU PERFIL REAL
-------------------------------------
Con la prueba bien, crea tu perfil de verdad en una sesión NUEVA de Claude Code arrancada SIN
CAI_DATA_DIR (ventana de PowerShell nueva):

      /update-profile

Ten a mano tu CV (PDF o texto). El agente ejecuta cai profile init, lo rellena contigo sección a
sección, te pregunta niveles F/C+/C/B, métricas, NDAs e historias STAR, y al final lo valida, lo
importa y te enseña el diff. data/profile.yaml nunca va al repositorio.


QUÉ ME TIENES QUE CONTAR
------------------------

- La respuesta de Claude en los pasos 13 y 14, sobre todo si vio algún dato de contacto o salario.
- Si te pidió permiso para get_profile.
- La salida del paso 16.
