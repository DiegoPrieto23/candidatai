# Fase 23.1 · Renombrado a CandidatAI

Primera de las cinco subfases de `dev/prompts/23-candidatai.md`. Rama `fase/23-candidatai`, un commit.

## Contexto
Lee `dev/prompts/23-candidatai.md`, `AGENTS.md`, `docs/AGENTS_COMPAT.md`, `.agents/manifest.yaml`,
`scripts/sync_agents.py`, `backend/pyproject.toml`, `backend/app/core/config.py`,
`backend/app/mcp/server.py`, `backend/app/services/agent_launch.py`, `agent_runner.py` y
`agent_output.py` (prefijo de las herramientas MCP en el segundo plano, ADR-032) y
`.claude/settings.json`.

## Alcance
1. **Nombre visible** «Job Hunter» → **CandidatAI** en la UI (cabecera, `<title>`, textos), la
   extensión (`"name": "Enviar a CandidatAI"`, popup, opciones, README; la `key` no cambia, así que
   el id de la extensión sigue siendo el mismo), las instrucciones del servidor MCP, los mensajes
   de la CLI, los skills y roles (`.agents/`), los docs, el README en los dos idiomas, `SECURITY.md`
   y `CONTRIBUTING.md`. El logo de la UI pasa de «JH» a «CA». No se reescribe el historial:
   `dev/ROADMAP.md` (registro), `dev/RESUMEN_FASES.md` y los `dev/prompts/` de fases anteriores se
   quedan como están; se añade una nota en el ROADMAP.
2. **CLI:** `[project.scripts]` pasa a `cai = "app.cli:app"` y `cai-mcp = "app.mcp.server:main"`.
   Sin alias `jh`. Todas las referencias a `jh …` (docs, skills, roles, mensajes de error, tests,
   `.claude/settings.json`, el manifiesto) pasan a `cai …`. El nombre del paquete Python pasa de
   `job-hunter` a `candidatai`.
3. **Variables de entorno:** `JH_*` → `CAI_*` con `AliasChoices` (primero `CAI_*`, después `JH_*`)
   para que un `.env` antiguo siga funcionando. `cai doctor` avisa si encuentra variables `JH_*` y
   dice cómo renombrarlas. El agente no puede leer ni editar `.env*`: la actualización de
   `.env.example` va a `dev/pruebas/PENDIENTES.md`.
4. **Servidor MCP:** `jobhunter` → `candidatai` (`SERVER_NAME`, manifiesto, `mcp_prefix`
   `mcp__candidatai__`, `agent_output.MCP_SERVER`, el respaldo de `agent_runner`). Regenera con
   `sync_agents.py`. En `.claude/settings.json` (a mano) los permisos `mcp__jobhunter__*` pasan a
   `mcp__candidatai__*`.
5. **Base de datos:** el fichero por defecto pasa a `data/candidatai.db`. Si no existe y sí existe
   `data/jobhunter.db`, se usa ese (sin moverlo ni copiarlo); `cai doctor` lo dice. La demo crea
   `candidatai.db`.
6. **Otros identificadores:** claves de `localStorage` (`jh-theme` → `cai-theme`, leyendo la
   antigua una vez), nombres de cabeceras o ficheros con `jh` si los hay, `User-Agent` de los
   conectores (`CandidatAI/0.1 …`), etiquetas de Playwright y del navegador de la candidatura.
7. **Fuera del repositorio:**
   - busca referencias a `jh` o `jobhunter` en la configuración de usuario del agente (en Claude
     Code, `~/.claude/settings.json`) y en las notas de memoria del agente; enseña al usuario qué
     cambiarías antes de tocar nada fuera del repositorio;
   - renombra el repositorio de GitHub (`job-search` → `candidatai`) con `gh repo rename`, solo con
     el OK del usuario, y actualiza el remoto local. La carpeta local no se toca;
   - añade a `PENDIENTES.md`: `uv sync` con el agente cerrado, renombrar `JH_*` en `.env`, revisar
     si tiene algo propio (accesos directos, tareas programadas) que llame a `jh`.
8. **Docs:** ADR nueva (nombre y renombrado técnico, con las compatibilidades que quedan),
   `AGENTS.md` (título, comandos, convenciones) y la tabla de comandos de `AGENT_INTERFACE.md`.

## Criterios de aceptación
- `git grep` no encuentra «Job Hunter», `jobhunter` ni el comando `jh` fuera del historial y de
  las compatibilidades documentadas (`JH_*`, `data/jobhunter.db`).
- Un `.env` solo con `JH_*` sigue funcionando (test) y `cai doctor` lo avisa.
- Con solo `data/jobhunter.db`, la app la usa (test).
- La paridad MCP ↔ CLI sigue en verde con `cai`; el segundo plano deniega las herramientas con el
  prefijo nuevo (test).
- Tests en verde, ruff limpio, `sync_agents.py --check` en verde.
