# Fase 28.2 · Raíz limpia: lo interno, a `dev/`

Segunda subfase de `dev/prompts/28-lanzamiento-repo.md`. Rama `fase/28-lanzamiento-repo`, un commit hecho
con `git mv` (el historial de cada fichero se conserva).

## Contexto
Lee `AGENTS.md` (tabla de documentación y estructura), `CLAUDE.md`, `docs/README.md`,
`CONTRIBUTING.md`, `scripts/check_links.py`, `.github/workflows/ci.yml`, `.agents/skills/` (el skill
`implement-phase` y cualquier otro que cite `dev/prompts/` o `dev/ROADMAP.md`), `scripts/sync_agents.py`,
`backend/app/cli.py` (`cai eval`, que lee `evals/`) y `.gitattributes`.

## Problema
La raíz muestra al visitante lo que le da igual: `dev/prompts/` (80 encargos de fase, 77 ficheros lo
citan), `evals/` y, dentro de `docs/`, el ROADMAP de 240 KB, los ADR, las pruebas manuales y los
resúmenes de fase. GitHub no deja ocultar carpetas, así que se **mueven** y se marca lo generado.

## Alcance
- **Carpeta `dev/`** con lo que solo le importa a quien desarrolla la app o la construye con un agente:

  | Hoy | Pasa a |
  |---|---|
  | `dev/prompts/` | `dev/prompts/` |
  | `dev/pruebas/` | `dev/pruebas/` |
  | `dev/ROADMAP.md`, `dev/RESUMEN_FASES.md`, `dev/DESARROLLO_POR_FASES.md` | `dev/` |
  | `dev/DECISIONS.md` (ADR) | `dev/DECISIONS.md` |

  **Se quedan donde están:** `docs/` con lo que lee un usuario o quien contribuye (guías, arquitectura,
  modelo de datos, interfaz para agentes, políticas, plantillas de CV, fuentes, correo, agentes y
  modelos gratis, comparativa), `evals/` (es un argumento de calidad y el código la lee; moverla es un
  cambio de código que no compensa) y las carpetas de agentes (`.claude`, `.agents`, `.codex`, `.qwen`,
  `.opencode`, `.mcp.json`, `opencode.json`), que los agentes exigen en la raíz. `install.ps1` e
  `install.sh` tampoco se mueven: sus URLs de `raw.githubusercontent.com` ya son públicas.
- **Cero enlaces rotos.** Un script (`scripts/move_to_dev.py`, de un solo uso y con `--dry-run`)
  reescribe todas las referencias (`dev/prompts/`, `docs/ROADMAP`, `docs/DECISIONS`, `dev/pruebas`, …:
  ~200 ficheros), incluidos `AGENTS.md`, los skills de `.agents/` (y luego `sync_agents.py` regenera
  `.claude/`, `.codex/`, `.qwen/` y `.opencode/`), la CI, los tests que leen esos ficheros y las
  guías en los dos idiomas. `scripts/check_links.py` pasa a comprobar también los enlaces entre `dev/`
  y `docs/`, y la CI lo ejecuta.
- **Dos índices:** `docs/README.md` (para quien usa o contribuye) y `dev/README.md` (cómo se construye
  por fases, qué es cada carpeta). `AGENTS.md` los cita en vez de las rutas viejas.
- **`.gitattributes`:** `dev/**` y `docs/**` como `linguist-documentation`; `frontend/src/api/openapi.json`,
  `schema.d.ts` y las copias generadas (`.claude/`, `.codex/`, `.qwen/`, `.opencode/`)
  como `linguist-generated`. Así la barra de lenguajes de GitHub muestra Python y TypeScript y los
  diffs generados salen plegados. No se oculta nada del árbol.
- **Pistas en lo que no se puede quitar:** un `README.md` corto dentro de `.agents/` («fuente única de
  skills; `.claude/`, `.codex/`, `.qwen/` y `.opencode/` se generan desde aquí») para que el visitante no
  piense que son cuatro copias a mano.
- **No se toca** `docs/img/` ni `docs/video/` aquí: se rehacen en la 28.3.

## Pruebas
`scripts/check_links.py` y la CI en verde en los tres sistemas; `uv run scripts/sync_agents.py --check`;
`cai eval matching`; los skills `implement-phase` y `update-profile` leen las rutas nuevas; ningún
fichero de `dev/` cita una ruta vieja (`git grep` de las rutas antiguas sale vacío).

## Criterios de aceptación
En la raíz ya no están `dev/prompts/` ni los documentos internos, la barra de lenguajes de GitHub enseña
Python y TypeScript, y un clon nuevo pasa todos los tests sin una sola ruta rota.
