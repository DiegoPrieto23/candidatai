# Fase 28.3 · Medios nuevos y un README que recoge todas las funcionalidades

Tercera subfase de `dev/prompts/28-lanzamiento-repo.md`. Rama `fase/28-lanzamiento-repo`, dos commits:
**28.3a** (inventario de funcionalidades y comprobación automática) y **28.3b** (medios).
**No empieces hasta que la 27.4, la 27.5 y la 27.6 estén fusionadas**: enseñan pantallas que cambian.
Petición del usuario (2026-10-23): rehacer vídeos, GIF y capturas y mencionar todas las funcionalidades.

## Contexto
Lee `scripts/readme_media/README.md`, `illustrations.py`, `screenshots.py` y `recordings.py` (ya
generan todo desde la **demo**, nunca desde `data/`), `README.md`, `README.es.md`, `docs/GUIDE.md`,
`docs/GUIA.md`, `dev/RESUMEN_FASES.md` (lo que aporta cada fase), `frontend/src/App.tsx` (las
rutas) y `.agents/skills/` (los skills).

## Problema
El README cubre mucho, pero se ha quedado atrás: hay páginas sin captura ni mención (Calendario,
Respuestas, Alertas con varios buzones, «Mi perfil» editable, «Búsqueda», Plataformas con prioridades,
descartar desde la Bandeja, ayudas en los botones…), la mitad de las capturas son de antes de las fases
24-27, y los GIF y vídeos (~20 MB) pesan más de lo razonable.

## Alcance

### 28.3a · Inventario y comprobación
- **`docs/FEATURES.md` (y `FUNCIONALIDADES.md`)**: la lista completa y ordenada por el recorrido del
  usuario (conseguir ofertas → triar → CV y carta → candidatar → seguimiento y respuestas →
  entrevistas y ofertas → estrategia y perfil → ajustes y agentes). Cada funcionalidad con una frase, su
  skill o pantalla y su captura. El README resume y enlaza; no repite todo.
- **Fuentes del inventario:** las rutas de `App.tsx`, los skills de `.agents/skills/`, los apartados de
  `dev/RESUMEN_FASES.md` y los CHANGELOG. Si algo existe y no se puede explicar en una frase, es señal
  de que la UI no se entiende; se apunta como mejora, no se oculta.
- **`scripts/check_readme_coverage.py`** (en la CI): falla si una ruta de la UI o un skill no aparece
  en `FEATURES.md`/README en los dos idiomas, o si el README cita un skill que ya no existe, o si
  `README.md` y `README.es.md` tienen secciones distintas. Con una lista corta de excepciones
  explicadas. Así el README no vuelve a quedarse atrás.

### 28.3b · Medios nuevos (inglés y español)
- **Se rehacen todos**, con los scripts de `scripts/readme_media/` sobre la demo ya con todo (la 26.5
  la dejó completa): capturas de **cada página** (Inicio, Bandeja con el descarte, Por revisar, Alertas
  con buzones, Procesos, Calendario, Respuestas, Embudo, Skills, Plantillas, Mi perfil con Experiencia y
  Búsqueda, Fuentes → Empresas y Plataformas, Agente y la ficha de una oferta con CV, carta, paquete,
  proceso, entrevista y dosier), en claro y, las principales, en oscuro, a 1600×1000.
- **Escenas nuevas en `recordings.py`:** triaje con el teclado, descartar desde la Bandeja con
  «Deshacer», añadir un buzón de correo, CV con otra plantilla y color, candidatura asistida hasta el
  botón de enviar, «Mi perfil» plegable, y un **tour de 60-90 segundos** del recorrido completo.
- **Cómo se publican (peso):** las capturas, como `.png` optimizadas (o `.webp`) en `docs/img/`;
  los GIF solo si son cortos y pesan < 1,5 MB cada uno (gifsicle/ffmpeg); **los vídeos no entran en el
  repo**: se suben como activo de la release o a YouTube y el README enlaza a ellos con una miniatura.
  Presupuesto: los medios nuevos en git, ≤ 8 MB en total; los viejos se borran del árbol (el historial
  no se reescribe).
- **Vídeo del tour:** con subtítulos (la mayoría lo ve sin sonido), 1080p, en inglés y en español,
  sin datos personales (es la demo, con candidata ficticia). Opcional: una versión de 20 segundos para
  redes (vertical o cuadrada).
- **Accesibilidad:** `alt` descriptivo en cada imagen y transcripción breve del vídeo.
- **Ilustraciones:** el banner y el diagrama «cómo funciona» se revisan (mencionan el recorrido
  completo, incluidos entrevistas, ofertas recibidas y varios buzones) y se regeneran.
- **Imagen social** (1280×640) para GitHub y para compartir el enlace: se prepara aquí y se sube en 28.4.

## Pruebas
- El script de cobertura falla si se quita una página o un skill del README, y pasa con los dos
  idiomas al día.
- Revisión visual de cada captura (nada de datos reales, nada cortado, modo oscuro legible) y de los
  vídeos con el sonido apagado.
- `scripts/check_links.py` en verde; peso de lo nuevo dentro del presupuesto.

## Criterios de aceptación
Cada página de la UI y cada skill se explican en el README o en `FEATURES.md`, las capturas y
vídeos reflejan la app tal como es hoy en los dos idiomas, y un script impide que vuelva a haber
funciones sin contar.
