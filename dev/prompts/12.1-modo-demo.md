# Fase 12.1 · Demo y portfolio: modo demo

Primera de las tres subfases de `dev/prompts/12-demo-portfolio.md` (12.1 → 12.2 → 12.3). Las tres se
hacen en la misma rama, `fase/12-demo-portfolio`, con un commit por subfase.

## Contexto
Lee `dev/prompts/12-demo-portfolio.md`, `docs/DATA_MODEL.md` (eventos y proyección de etapas),
`docs/POLICIES.md` §6 (privacidad) y `demo/` (`profile.example.yaml`, `photo.png`, `jobs/`).

Reutiliza:
- `services/events.record()` con `occurred_at` en el pasado para fechar el historial;
- `services/ingest`, `services/extractions` y `services/matching` para dar de alta, extraer y
  puntuar sin atajos en la BD;
- `services/documents/service` para guardar, verificar y renderizar los CVs;
- `services/analytics` para comprobar que el embudo sale con datos.

## Objetivo
Cualquiera que clone el repo tiene, con un comando, una app llena de datos ficticios creíbles y
sabe en todo momento que está viendo una demo.

## Alcance
1. **Catálogo ficticio** `demo/seed/catalog.yaml`: empresas, puestos, ciudades, modalidades,
   skills por puesto, fuentes y motivos de descarte inventados. Sin nombres de empresas reales.
2. **Generador** `app/services/demo.py`, determinista (semilla fija, misma salida en cada
   ejecución), que crea `data-demo/` con:
   - `profile.yaml` (copia de `demo/profile.example.yaml`) y la foto (`demo/photo.png`);
   - unas 60 ofertas con su `JobExtraction` y su match, repartidas entre fuentes;
   - eventos repartidos en las 8 semanas anteriores a hoy, de modo que el dashboard tenga forma:
     descartes con motivo, aprobadas, aplicadas, respuestas, entrevistas con hitos (alguno
     futuro, para el calendario), alguna oferta, rechazos, sin respuesta y seguimientos vencidos;
   - dos CVs generados y verificados para dos ofertas (contenido ficticio sacado solo del perfil
     demo). PDF con LibreOffice o Word (`ats-simple`) o, si no hay, con Chromium de Playwright
     (`moderna-2col`); sin ninguno, la demo se crea sin CVs y lo avisa: el seed no falla en una
     máquina limpia;
   - el fichero marca `data-demo/.demo`.
3. **Seguridad del seed:** si la carpeta destino existe sin la marca, se niega a tocarla. Si
   existe con la marca, pide `--force` para recrearla. Nunca escribe en `data/`.
4. **CLI** `jh demo seed [--dir data-demo] [--force]` (capa fina). Imprime el resumen y cómo
   arrancar: `JH_DATA_DIR=data-demo` para `jh serve` (y para el MCP, si se quiere probar con un
   agente).
5. **Banner:** `Settings.demo_mode` es verdadero si existe la marca en `JH_DATA_DIR`. `GET /status`
   lo expone y la UI muestra un banner fijo («Modo demo: datos ficticios») en todas las páginas.
   Cliente de API regenerado.
6. `.gitignore`: `data-demo/`. Sección corta en el README sobre cómo arrancar la demo.

## Decisiones tomadas al planificar
- Las ofertas se generan combinando el catálogo en código, no con 60 ficheros a mano: así el
  volumen se ajusta sin tocar datos y el resultado es reproducible.
- La extracción y los CVs los guarda el generador por los servicios de siempre (actor `agent`)
  con `agent_name: "demo-seed"`, para que la auditoría deje claro que no los hizo un agente real.
- Fechas: los servicios fechan «ahora» lo automático (alta, extracción, filtros, score); el
  generador lo lleva después al día del alta y recalcula la proyección. Los pasos del usuario
  (triaje, envío, respuestas, hitos) se registran ya con su fecha (`occurred_at`).
- Sin migraciones: todo usa el esquema actual.

## Criterios de aceptación
- `jh demo seed` sobre una carpeta temporal: unas 60 ofertas, eventos dentro de las 8 semanas,
  `get_funnel_stats` con datos en todos los pasos y 2 CVs verificados.
- Dos ejecuciones con `--force` producen el mismo contenido (salvo fechas relativas a hoy).
- Se niega con una carpeta sin marca y con una con marca sin `--force`.
- Test de Vitest: el banner sale con `demo_mode` y no sale sin él.
- Prueba manual: `jh demo seed`, `JH_DATA_DIR=data-demo jh serve` y `pnpm dev` muestran la app
  llena con el banner.
