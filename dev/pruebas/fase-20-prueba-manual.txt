PRUEBA MANUAL · FASE 20 · CALIBRACIÓN Y PATRONES («¿ACIERTA EL SCORE?»)
=====================================================================

Objetivo: comprobar con datos de verdad que
- la sección «¿Acierta el score?» del Embudo cuadra con lo que sabes de tus candidaturas;
- `cai stats calibration` dice lo mismo que la UI;
- el skill review-search hace una retrospectiva prudente (no saca conclusiones con pocos datos)
  y NUNCA cambia config/policies.yaml ni tu perfil.

Las cifras exactas ya las prueban los tests con un histórico sintético. Aquí se mira si tienen
sentido con tus datos y si el agente las lee bien. Tiene sentido a partir de unas 20-30
candidaturas enviadas; con menos, haz las partes 1 y 2 con la demo.
Duración aproximada: 15-20 minutos.


REQUISITOS
----------
- Rama: fase/20-calibracion-patrones (o main, si ya está fusionada). Sin migraciones nuevas.
- API y UI arrancadas en sus ventanas (cai serve y pnpm dev), fuera de tu agente.
- Abre Claude Code de nuevo para que el MCP cargue `get_calibration` (/mcp).
- Opcional, sin tocar tus datos: la demo (21 enviadas, sin veredictos, cartas ni plantillas):
      uv run --directory backend cai demo seed --dir data-demo
  y arranca la API con  $env:CAI_DATA_DIR = "data-demo".


PARTE 1 · La sección en el Embudo (5 min)
-----------------------------------------
1. Abre «Embudo». Al final, antes de «Motivos de descarte», está «¿Acierta el score?».
   [ ] Sale el aviso «Orientativo…» con el intervalo al 95 % y `cai eval matching`.
   [ ] La línea de arriba (N enviadas · respuesta · entrevista) coincide con el embudo: «Enviadas»
       y «Con respuesta» del panel de arriba (con el periodo «Todo»).
2. Pestaña «Score»: siempre cinco filas (< 60, 60-74, 75-84, ≥ 85, Sin score).
   [ ] Cada fila: enviadas, respuesta con su intervalo entre paréntesis y la barra (banda clara =
       intervalo, marca = tasa), entrevista y esperando.
   [ ] Las filas con menos de 10 enviadas llevan «pocos datos»; las de 0, guiones y sin marca.
3. Recorre «Veredicto», «Fuente», «Portal», «Plantilla», «Carta», «Referencia» y «Rapidez».
   [ ] Elige dos o tres candidaturas que conozcas bien (p. ej. una con carta y referencia) y
       comprueba que caen en el grupo correcto de cada pestaña.
   [ ] Una oferta que valoraste DESPUÉS de enviarla sale como «Sin valorar» (a propósito: un
       veredicto posterior pudo escribirse sabiendo cómo fue).
4. Cambia el periodo a «30 días».
   [ ] La calibración cuenta las enviadas en esos 30 días (por fecha de ENVÍO, no de alta): puede
       no coincidir con «Enviadas» del embudo de arriba, que va por fecha de alta.
5. Con un periodo sin envíos (p. ej. «Desde» mañana): «Aún no has enviado ninguna candidatura…».


PARTE 2 · La CLI (2 min)
------------------------
Desde la raíz:

    uv run --directory backend cai stats calibration
    uv run --directory backend cai stats calibration --since 2026-09-01 --min-cases 5

   [ ] Las cifras coinciden con la UI (las tasas, redondeadas).
   [ ] Solo lista los grupos con envíos y marca «(pocos datos)».
   [ ] `--min-cases 0` da error de validación.


PARTE 3 · La retrospectiva con tu agente (10 min)
-------------------------------------------------
1. Antes, haz una copia para comparar:
       copy config\policies.yaml data\tmp\policies.antes.yaml
2. En la UI, botón «Revisar mi búsqueda» (se abre en terminal) o, en Claude Code:
       /review-search
   [ ] Llama a get_calibration y get_funnel_stats (y lee config/policies.yaml).
   [ ] Con menos de 20 enviadas, avisa de que es orientativo y pregunta si sigue.
   [ ] Da cifras con su x/n e intervalo, y llama «pocos datos» a los grupos con low_data sin
       sacar conclusiones de ellos.
   [ ] Si dos intervalos se solapan, dice que no se ve diferencia (no «A funciona mejor que B»).
   [ ] Propone como mucho 5 cambios, cada uno con evidencia, confianza y el cambio concreto. Los
       de configuración, con el valor exacto y los pasos de `cai eval matching` antes y después.
3. Pídele que aplique uno de los cambios de configuración que proponga.
   [ ] Se niega a editarlo y te da el cambio y los pasos para que lo hagas tú.
4. Comprueba que no ha tocado nada:
       fc config\policies.yaml data\tmp\policies.antes.yaml
   [ ] «no se han encontrado diferencias». Tampoco cambia data/profile.yaml (git status limpio
       fuera de data/).


SI ALGO FALLA
-------------
- La sección no sale o da error: mira la consola de la API (GET /stats/calibration).
- `get_calibration` no aparece en el agente: reinicia Claude Code (/mcp).
- Un grupo te parece mal asignado: las reglas exactas están en docs/DATA_MODEL.md §Calibración.
  Apunta el job_id y el grupo esperado en dev/pruebas/PENDIENTES.md.
