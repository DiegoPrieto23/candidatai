# Fase 23.4 · Instalación fácil y arranque con un clic

Cuarta subfase de `prompts/23-candidatai.md`. Rama `fase/23-candidatai`, un commit.

## Contexto
Lee `backend/app/cli.py` (`serve`, `worker`), `backend/app/api/main.py` y `deps.py` (CORS y
`require_ui` con `UI_ORIGIN`), `backend/app/services/worker.py`, `frontend/vite.config.ts` y
`frontend/src/api/client.ts` (`VITE_API_URL`), `.github/workflows/ci.yml` y `docs/GUIA.md` /
`docs/GUIDE.md`. ADR-002 y ADR-007 (SQLite, nativo en Windows, sin Docker).

## Problema
Hoy, para usar la app hacen falta uv, Node y pnpm, y tres terminales (`serve`, `worker`, `pnpm
dev`). Mucha gente solo quiere usar la herramienta.

## Alcance
1. **La API sirve la UI compilada.** Si existe la carpeta de la UI construida (`frontend/dist/` o
   la que traiga la release), FastAPI la sirve en `/` con respaldo a `index.html` para las rutas
   del cliente, sin tapar las rutas de la API. La UI compilada llama a la API en su mismo origen.
   `require_ui` y CORS aceptan `http://127.0.0.1:8000` además de `http://127.0.0.1:5173`
   (desarrollo). Nada escucha fuera de `127.0.0.1`.
2. **`cai start`:** aplica las migraciones, comprueba que hay UI compilada (si no, explica cómo
   conseguirla), arranca la API y el worker como dos procesos hijos supervisados, espera a que la
   API responda y abre el navegador en `http://127.0.0.1:8000`. Ctrl+C (o cerrar la ventana) para
   los dos. Si el puerto está ocupado por otra CandidatAI, abre el navegador y sale; si lo ocupa
   otra cosa, lo dice. Un log de los dos en `data/logs/`.
3. **Releases:** workflow de GitHub Actions que, al crear una etiqueta `v*`, compila la UI y
   publica un zip con el backend, la UI compilada, `config/`, `templates/`, `demo/`, `extension/` y
   los docs. Sin datos personales ni `data/`.
4. **`install.ps1`** (en la raíz), pensado para `irm <url> | iex`:
   - instala uv si falta (instalador oficial);
   - descarga la última release y la descomprime en `%LOCALAPPDATA%\CandidatAI\app` (o actualiza
     una existente sin tocar `data/`, que va en `%LOCALAPPDATA%\CandidatAI\data` mediante
     `CAI_DATA_DIR`);
   - `uv sync`, `playwright install chromium` y `cai db upgrade`;
   - crea accesos directos «CandidatAI» en el escritorio y en el menú Inicio que ejecutan
     `cai start`, con el icono de la app;
   - explica qué ha hecho y cómo desinstalar (`install.ps1 -Uninstall` borra la app y los accesos
     directos, nunca `data/` sin confirmación explícita).
   No pide permisos de administrador. Para desarrollo, `cai start --dev` arranca también Vite.
5. **Icono** de la app (`.ico` para Windows) generado con `scripts/build_icons.py` a partir del
   monograma provisional «CA». Es provisional: la 23.5 diseña el logo y regenera el `.ico`.
6. **Docs:** guía de instalación en los dos idiomas (`GUIA.md`, `GUIDE.md`): para usarla (instalador)
   y para desarrollar (clonar). README en los dos idiomas, «Pruébalo en 5 minutos». Aviso: mientras
   el repositorio sea privado, el instalador de una línea solo funciona con una release accesible.
7. **Tests:** la API sirve la UI y su respaldo sin tapar `/status` ni otras rutas; `require_ui`
   acepta los dos orígenes y rechaza los demás; `cai start` arranca y para los hijos (con procesos
   falsos); el workflow de release se valida en seco; `install.ps1` con un modo `-WhatIf` que no
   toca nada.

## Criterios de aceptación
- Con la UI compilada, `cai start` deja la app usable en `http://127.0.0.1:8000` con worker, en un
  solo comando, y Ctrl+C no deja procesos huérfanos.
- `install.ps1 -WhatIf` describe los pasos sin cambiar nada; la prueba manual completa del
  instalador queda en `docs/pruebas/`.
- La UI en desarrollo (`pnpm dev`, 5173) sigue funcionando igual.
- Tests en verde, ruff limpio, `sync_agents.py --check` en verde, frontend en verde.
